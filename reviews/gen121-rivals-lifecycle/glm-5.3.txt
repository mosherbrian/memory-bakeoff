VERDICT: DEFECTS_MINOR

The core Gen121 repair is genuine and correctly ordered — the transport `try` holds only byte receipt (`urlopen`/`read`/`status`), the journal append (with `os.fsync`) sits outside it and before any decode, undecodable/malformed 200s are terminal with bytes kept on disk, nothing after byte receipt can retry or replace a response, and grade→closure→marker is written last over a verified inventory — but the "refuses to resume" guarantee is carried by a gate that can never fire: `main` calls `EV.next_attempt` (which by construction returns a directory that does not exist) and then checks whether `reader_journal.jsonl` exists *in that fresh directory*, so the check is always vacuous, and its test exercises the function in isolation rather than the wiring — the exact "check that reads like protection" pattern this project keeps anatomizing.

1. Because the resume-refusal is dead at the call site, the only thing actually blocking re-exposure after an interrupted run is preflight's dirty-tree gate, and that protection evaporates the moment the interrupted attempt directory is committed (append-only evidence, the natural act): the tree is clean, `next_attempt` yields a fresh directory, and a re-run with the same `--authorised-by <generation>` string silently re-asks all 60 already-exposed cases — precisely the "replaying already-exposed cases" scenario `refuse_to_resume_an_exposed_run`'s docstring says it exists to prevent; the contract field `interrupted_run_is_not_resumable: true` and the CANONICAL_ATTEMPT/handoff narrative both attribute this protection to a mechanism that cannot deliver it.
2. The marker write computes `sorted({r["served_model"] for r in responses})`, which raises `TypeError: '<' not supported between instances of 'str' and 'NoneType'` in any run mixing at least one terminal disposition (undecodable/malformed/transport — all set `served_model: None`) with at least one completed response; the crash lands after all evidence is durably captured, sealed and graded but *before* the marker is written, permanently leaving the attempt marker-less (and backfill is forbidden). It fails closed — such a run was headed for NON_EVIDENCE anyway, since linkage requires 60 COMPLETED — but it means the runner cannot complete the very scenario the terminal-disposition machinery was built to record.
3. Authored self-attestation: every journal record carries `"captured_before_any_decode": true` and `raw_seal.json` carries `"written_per_call_and_fsynced": true` — literal constants vouching for the code that writes them, the same defect class as Gen114's `seed_accepted: true` that this same file explicitly disavows ("to be read from server evidence, never authored"); true of the frozen source, but assertions, not observations.
4. "The transport `try` contains exactly one thing" is not literally true: the `with` block's `__exit__` (socket close) and the `r.status` attribute read also execute inside the `try`, so an exception from either *after* a fully successful `r.read()` would discard already-received bytes and re-ask the case — the forbidden transition; with `http.client` both are effectively non-raising, so this is a hairline between the stated invariant and the actual block contents, not a live path.
5. `test_the_capture_is_fsynced_not_merely_flushed` is a source-string grep (asserting `os.fsync(handle.fileno())` appears in `evidence.py`) rather than a behavioral witness — the decayed-prose-check shape that attempt8 documented inside this same apparatus.
