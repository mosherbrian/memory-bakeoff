## Failed-experience reuse (the genuinely new mechanism)

Two findings worth keeping: (1) single-failure distillation misleads — full addition underperforms selective, because one failed trajectory lacks context for sound analysis (multi-failure comparison works, single-failure doesn't); admission must be retry-gated. (2) Utility deletion with a minimum-evidence floor (f ≥ 5 before judging) — prune only after enough recalls. Both transfer as *rules* to native files without any code.

## Deepened (c25): auto_dream + host paths from source

- **auto_dream is a different loop from the paper.** Source (`reme/steps/evolve/dream/`: extract → integrate → finish): extract finds changed/unchanged/deleted source paths; integrate runs an LLM agent (tools: node_search, read, write, edit, frontmatter) that writes digest memory under a serialization lock, with mtime+size snapshot digests for side-effect recovery; finish persists upserts/deletes. It requires an LLM ("dream integrate requires an LLM"). What I did **not** find: N=8 trajectory sampling, an LLM-judge validation gate, or utility-ratio (u/f) deletion — deletion here is catalog-sync of removed sources, not utility pruning. So the paper's refinement loop is **not present** in current auto_dream as read; a different agent-integration loop stands in its place.
- **Source records & originals:** `auto_memory` persists *filtered* conversation source records (recalled tool results and base64 omitted so retrieved content doesn't become source material) plus daily notes; digest holds the refined layer. Originals survive filtered, not verbatim — recovery reads filtered records + notes, weaker than pi-lcm verbatim but stronger than extraction-only stores. No explicit versioning found; file-native layout is git-compatible by construction (unverified whether the product commits).
