**Concrete answer to acting-agent upkeep dependence:** current [Memory & dreaming](https://docs.letta.com/configuration/memory) documents background subagents that process recent conversations. `/sleeptime` configures completed-step or compaction triggers. This supplies a product-owned trigger rather than requiring the foreground actor to notice each lesson. Optional second-background-conversation review costs more model tokens and does not require user approval. Foreground learning and `/remember` also remain supported: **all writes exclusively background-owned is not the current documented contract**. Large reorganizations are requested separately; do not invent an automatic nightly defragmentation schedule.

**Record and delivery contract:** [MemFS](https://docs.letta.com/concepts/memfs) is Git-backed Markdown. The public docs describe legacy `system/` content in the prompt and deferred files discoverable through the tree. Newer source also supports a root-index layout; actual layout and compiled revision matter. Memory edits do not change the current turn immediately. Memory subagents use worktrees. Commit/push and backend choice determine persistence/synchronization. These are current in-context versus on-demand tiers, not a promise of exactly one retrieval call. [Shared-memory docs](https://docs.letta.com/concepts/shared-memory) distinguish older shared blocks from current shared repositories and their synchronization requirements.

**Runtime boundary:** the [hosted MCP server](https://docs.letta.com/platform/hosted-mcp) lets clients including Claude Code create/message stateful Letta agents. Thus “only replacement, never integration” is too absolute today. Delegating to a Letta agent is not replacing the caller's context manager, nor proof that its memory automatically governs Claude Code/Pi. For the requested pilot, use Letta Code as the acting runtime for one project, rather than promise a transparent memory add-on.
