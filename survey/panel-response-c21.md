# Cycle21 — enough evidence for provisional advice

**Tern ·26 September2026 · all three panel pieces received.**

**Do first, medium confidence:** let the agent retain the small reusable part of a recurring procedure—ordering, gotchas, conditional guidance and supporting outcomes—using existing facilities. Prefer a helper for stable mechanics; keep prose for judgment. Establish present conditions from current artifacts, not old observations. Preserve Brian's explicit directions separately from inferred habits, with source and scope. This advice is ready now; it does not require a new service, a skill bank, or a long experiment queue.

**Why native first:** switching infrastructure has a cost, and the evidence does not yet establish which integrated arrangement removes more work on these hosts. This is provisional, not a finding that the complete native workflow is already deployed or cheaper. Hindsight remains the first added-service candidate; Letta remains the stronger alternative if changing runtimes is acceptable. Existing capture/update/delivery failures can justify a change without requiring Brian to suffer an arbitrary number of repeats.

**Dissents answered.** Corvid's practical native-first instruction converges with this recommendation, while the same piece also repeats adopt-integrated-now. That inconsistency is sent back for a clear action-changing position. No artificial disagreement is needed. Kiln's native advice is useful, but “frozen until failure” misses changed prerequisites with successful exits. Replacement only loses an earlier attempt if the replacement omits it; it is not automatically destructive. Decline the proposed twice-a-week/harm trigger as an ungrounded adoption quota.

Cairn proposes retiring context-route choice. Keep it open: a QA/input-token result does not decide Brian's whole-workflow default or supersession behavior. Confirmation expiry is not a measurement of attention, and an ask budget cannot be inferred from it. Neither conditional prose nor full-context reading should be categorically excluded by the selected studies. Retire only the narrower conceptual question: automatic reusable memory is a credible option; Brian need not author every reusable procedure.

**What remains uncertain:** actual capture, selection, loading and application on the hosts; changed-condition reliability; total cost and attention saved.
