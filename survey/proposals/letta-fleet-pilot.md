# Approval proposal — one fleet-operated Letta memory trial

Tern ·26 September2026 · **Design only; Brian's approval required before setup/model calls/execution.** Supersedes the personal one-week Letta proposal. Brian keeps his runtimes. One fleet operator (proposed: Claude) drives isolated seats; Tern freezes the task/score manifest and reports the comparison. No Letta Cloud, mobile trial, real-project edits, private transcript import, training or recurring campaign.

**Question:** on a small scripted stream, does Letta Code's supplied memory/maintenance reduce repeated instruction and improve later correct action over ordinary native-file upkeep, without learning wrong lessons at excessive cost? This is an arrangement comparison, not an isolated causal test of reflection or proof of benefit on Brian's real work.

## Arms and execution path

- **L — Letta Code local backend**, persistent local agent/memory, built-in reflection enabled with one declared trigger setting frozen before scoring. New conversation at each session boundary; do not create a new agent. Foreground/background models and all reflection calls recorded. No operator `/remember` hints or hand-edited memory.
- **N — native Pi files/skills**, persistent isolated project memory, new conversation per session, ordinary actor-owned upkeep enabled. Same initial instruction to retain useful scoped lessons; no supplied nightly reflector or operator repair. Pi is the primary comparator to keep model/provider matched. Claude Code is a fallback comparator only if it can use the same chosen model/provider; otherwise a changed-model run is not this matched comparison.
- **B — optionB stage1**, optional third arm in the same experiment **only if already operational before the run manifest is frozen**. Same native host/model as N, existing stage1 functionality pinned; no building a compiler gate or reflector merely to include it. Otherwise record “not ready, omitted.” No phase2 Vault/Ledger/Laya training.

Prefer official `letta-ai/letta-acp` with backend explicitly `local`, persistent local agent ID and pinned model handle, if agent-deck can drive its advertised ACP session surface. Agent-deck compatibility is not established by adapter existence. If it cannot, use a supported headless Letta Code invocation with the existing fleet driver; spend at most30 operator minutes resolving the route, then stop as setup-inconclusive rather than invent an adapter. No cloud-oauth fallback: that backend stores state in Letta Cloud even though tools run locally. Direct model access still sends the synthetic prompts to the chosen provider.

The adapter documents the local runtime and session lifecycle; Letta documents local ChatGPT subscription access. These are product claims, not a successful local login test. [Official adapter](https://github.com/letta-ai/letta-acp), [Letta model providers](https://docs.letta.com/configuration/models). OpenAI distinguishes subscription sign-in from usage-based API-key access, but its documentation does not certify third-party Letta compatibility. [OpenAI authentication](https://learn.chatgpt.com/docs/auth).

## Model, cost and hard stop

**Preferred route:** existing ChatGPT OAuth entitlement, same explicit supported model handle and reasoning setting across L/N and optional B. Record resolved model/provider, harness/adapter revisions and auth mode before scored sessions; no auto-routing or silent model fallback. Do not claim a model name works until both hosts expose it. If no common model is available, stop before scoring and report the mismatch.

**Proposed financial authorization:** **$0 additional purchases/API spend** on the OAuth route; existing subscription quota is consumed and is not free compute. No credits/top-ups or API-key fallback. Record token/request usage, quota change where exposed, background calls, wall time and operator minutes. Existing subscription cost is sunk and cannot be converted into an invented per-trial dollar charge. [OpenAI pricing distinctions](https://learn.chatgpt.com/docs/pricing).

**Alternative in the approval scope:** the existing Go pool only if both hosts support the same provider/model and its current accounting/rates are available: at most **$5 total pool debit**, all arms/setup/background work included, no paid overflow. This is a proposed ceiling, not a price estimate or a claim of verified Go compatibility. Freeze one route before scoring; do not switch routes mid-run. If the pool cannot expose a defensible cost bound, use OAuth or stop.

**Resource ceiling across the experiment:**90 model requests including foreground, reflection and setup;500k input tokens and40k output tokens where enforceable accounting exists;3 elapsed hours after setup, with at most30 operator setup minutes. Each arm gets an equal maximum30 model requests, with optional B consuming the third allocation; unused budget is not transferred. Stop before a call whose configured maximum would exceed remaining allowance. If the runtime cannot bound/account for background work, do not let an unattended worker run beyond the trial; classify the operational limit as inconclusive. No follow-on run automatically authorized.

## Seven sessions, six planted lessons

Use separate identical synthetic fixture directories per arm, no shared writable memory. Gold score manifest is held outside the seats' readable scope. Freeze exact prompts, fixture hashes, model/settings, triggers and check predicates before any model sees scored tasks. Interleave arm order by session, alternating which arm goes first. Retain output artifacts, tool events and memory revisions; never feed scores or another arm's records back except the predefined correction below.

| Session | Script and intended observation |
|---|---|
| 1 — preferences | Explicitly teach two arbitrary scoped preferences: Atlas release reports use ordered fields `impact`, `checks`, `rollback`; Beacon reports use `summary`, `evidence`, `next`. Ask one acquisition example each. These are sponsor directions, not inferred habits. |
| 2 — corrections | Show two old directions, then explicit replacements: Atlas release channel `oak` changes to `cedar`; Beacon artifact tag prefix `draft-` changes to `ready-`. Retain old statements in history. Each later task requires a dry-run manifest using the current value; no actual deployment. |
| 3 — procedures | Two deterministic toy work routines: export needs `prepare` before `export` and manifest checksum verification; restore needs a format-v2 conversion before import plus object-count verification. Allow at most two acquisition failures per routine with fixed tool feedback, then supply the same successful worked trace to every arm. Record acquisition failures separately. This plants experience-grounded procedural lessons without assuming a model invents them equally. |
| 4 — intervening work | Unrelated file-summary task plus a quoted third-party example containing an incompatible report style; explicitly quoted, not a sponsor instruction. No lesson reminder. Allow configured Letta reflection to finish within its resource budget; baseline gets ordinary closeout. No operator-authored summary. |
| 5 — first later use | Fresh conversation: six new task instances, one per lesson, no rule restatement. Check first completed artifact/tool sequence before remedial hints. |
| 6 — delayed reuse | Another fresh conversation: six more instances with changed incidental filenames/values but the same relevant scope/prerequisites. Score before hints again. |
| 7 — wrong-learning controls | Four distinct cases: Atlas report rule must not govern Beacon; Beacon prefix must not govern Atlas; third-party quoted style must not replace either sponsor preference; a format-v3 restore must not receive the learned v2 conversion. Task supplies its current environment where needed. No correct generalized rule is penalized for re-observing state. |

Each scored task gets the same fixed action/turn limit. After a failed positive task in sessions5/6, provide **one identical prewritten corrective reminder** and allow one retry within the arm budget; record both whether it repaired and the reminder. Initial teaching in sessions1–3 is not a repeat. Failure after the reminder is recorded unresolved, not extrapolated into imaginary additional corrections. No adaptive coaching. Pass/fail checks examine produced fields/values and required tool actions/output checks, not the agent's explanation or an LLM grader. Procedure fixtures intentionally allow reconstruction from their tool feedback; improved rediscovery effort counts separately from correct final action.

This is a concrete script specification; runnable toy tools/driver and exact prompt files are preparation within an approved experiment, not already built or executed. Their deterministic checks must pass against hand-written good/bad examples before scoring; no separate pilot campaign.

## Metrics and pre-stated decision

Primary counts per arm: **correct first-attempt later applications out of12**, **scripted repeat reminders out of12**, and **wrong learned applications out of4 controls**. Also report post-reminder repairs/unresolved tasks, acquisition failures, invalid learned entries only where traceable, model calls/tokens/cost, reflection time and operator repair effort. Stored/committed/loaded/applied are different observations; outcome artifacts drive the score. Do not count silence as successful learning.

**PASS for pursuing Letta as a fleet memory runtime** only if all hold: L completes the sequence within caps; at least10/12 later applications correct; at least2 more correct than N; at least2 fewer repeat reminders than N; **0/4 wrong-learning controls**; and no cross-arm access or unplanned operator memory repair. These thresholds are a practical pilot decision, not statistical significance. Reminder and first-attempt counts are linked by the fixed correction policy, so they are not independent confirmations of benefit. If B is included, L must also be no worse than B on later-use correctness, repeats and wrong-learning controls to be the preferred candidate; report costs without hiding reflection overhead.

**FAIL to justify a switch** if a completed valid run misses any criterion; keep the incumbent. A baseline ceiling or tie means no demonstrated advantage here, not proof Letta never helps. **INCONCLUSIVE** for route/model mismatch, tool/harness failure, cap/quota exhaustion before completion, contaminated isolation or unreadable scoring evidence; retain artifacts and stop without rerunning. Letta-caused omissions/failed memory updates with otherwise valid task execution are behavioral failures, not conveniently discarded trials.

One result table and a short decision finish this experiment. No mandatory extension, more seeds or week-long adoption. Brian need only approve or decline the proposal; he does not operate either arm or label each turn. **Confidence: medium in feasibility, low-to-medium that this small synthetic test predicts personal-work benefit.**
