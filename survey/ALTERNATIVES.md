# Practical arrangements: agents do the upkeep

**Tern · cycle40 ·26 September2026 · recommendation, not deployment. Medium confidence.**

Start with existing host facilities and agent-maintained guidance. When a worthwhile tool or default fix removes recurring mechanical work, prefer it to repeatedly explaining the steps. Keep useful rationale, limits and source evidence. For work requiring judgment, let agents draft and revise compact guidance from experience; Brian supplies goals and corrections, not routine clerical upkeep.

| Operation | Starting arrangement | What remains to make it reliable |
|---|---|---|
| Capture | Acting agent saves useful lessons and source pointers using existing note/skill surfaces; retain session evidence through current history facilities. | Choosing what matters, preserving failures, avoiding speculative lessons becoming facts. These are proposed working practices, not measured fleet savings. |
| Revise | Agent distinguishes a bad method, bad application and changed conditions before updating guidance. Use history where committed. | Correct interpretation, actual commits/recovery, scope and supersession. No mandatory schema, vote threshold or per-record metric. |
| Deliver | Canonical guidance with host views; small core or selective detail according to relevance and cost. | Refreshing each host, discovering the right entry, loading and following it. A shared file or API does not establish these steps. |
| Recover | Existing transcript/log access, pi-lcm search/expansion and committed file history where available. | Finding the decisive evidence and knowing which version applies. Historical recoverability does not mean continuing to recommend old guidance. |

This arrangement is advice assembled from inspected facilities, not an installed cross-host system. Claude, Pi and local-agent hosts have different insertion paths. Prose triggers are not the complete selector. A narrow checker establishes its tested property, not the correctness of an entire procedure.

**Automation remains a real alternative.** ReMe is the file-compatible capture/consolidation comparator; its current product differs from the research-paper loop. Pi reflection can automate transcript-to-file upkeep where that is the actual gap. Hindsight is a comparator for derived observations and retrieval with host adapters; Letta is a broader runtime alternative. Their existence does not establish that Brian needs a service, nor that hand-assembled upkeep is cheaper. Choose the operation removed and count model calls, operating effort, correction and refresh work left behind.

**What changes the choice:** a concrete arrangement that reduces rediscovery and repeated correction more than it adds misapplication and upkeep on Brian's actual hosts. No arbitrary incident quota or presumed dominant bottleneck. Stronger-model authorship and weaker-model execution are promising, but cheap acquisition and reliable local-model maintenance are not established by those labels.

Keep explicit sponsor directions separate from inferred tendencies. Share durable learning by scope and hand off live task state explicitly. Preserve relevant disagreement and recoverable evidence. The roadmap's five responsibilities remain useful; none requires its own service.
