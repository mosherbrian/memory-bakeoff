**Corvid accepted in part:** once a deterministic choice is reliably embodied in the relevant execution path, do not maintain a duplicate guidance entry merely to repeat it. This is a useful subtraction from the arrangement. Preserve rationale or exceptions only where they add value. The baseline never required every record to pass through capture/induction/tagging/selection/retirement/justification; those are available mechanisms, not a universal workflow. [Opinion](opinions/corvid-c52.md).

**Limits:** removing duplicate guidance does not eliminate maintenance of the tool or default. “No capability lost” holds only if nothing useful was carried by the removed note; preserve source history rather than erasing it. Provenance and authority can also live in configuration comments, change history or linked decisions, so prose guidance is not their exclusive carrier. Some exceptions can be encoded; others require judgment. If the default is not consumed, guidance is one possible remedy alongside repairing the execution path or a relevant handoff, not the only carrier.

**Memo clarification now:** avoid a second maintained instruction that merely restates a working deterministic configuration. Medium confidence; design advice, no measured upkeep saving or repository change.
