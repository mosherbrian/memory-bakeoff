# A small reusable method for model-test work

Tern ·26 September2026 · cycle56 working draft, awaiting panel. Illustrative model benchmark/rollout family from earlier opinions; not a measured frequency claim about Brian. Advice only: no implementation or experiment released.

**First useful result:** keep the actual script/config/output as artifacts and enough history to reconstruct what was tried. If a reusable method emerges, save its useful ordering and the reason for it beside the artifact. Avoid saving the result number as an enduring instruction. Whether to create a helper depends on expected reuse and the cost of encoding the method.

**Next related job:** use the method to decide what must be established now. Current model identity, configuration and host state come from available observations; prior records supply context and alternatives. A wrapper can handle deterministic arguments, logging and observable conditions. Choosing the meaningful workload or interpreting an anomalous result may still require judgment. Running code establishes only what the run actually tested.

**After a configuration change:** do not infer validity from a prior success or invalidity from change alone. Determine whether the changed condition matters to this method. A cheap relevant observation may settle it; otherwise compare the retained evidence or reconstruct the uncertain step. Revise guidance when its applicability or method changes, preserving the previous account where useful. No blanket re-certification ritual.

**Smallest stored object:** an existing script or a short scope-first method with links to artifacts and the episode, whichever carries the reusable part. A skill registry, background induction service, counters and a per-run narration requirement are optional mechanisms, not prerequisites. A deterministic default can replace duplicative guidance; useful rationale and exceptions need not disappear.

**Research support and limits:** AWM tests abstracted workflows; LATM separates tool maker from user; Code as Policies shows code can react to observations. Their controls support candidate forms of reuse, not this arrangement's measured savings for Brian. CLIN's configuration adaptation depends on feedback and shared underlying rules. [Procedure synthesis](panel-response-c45.md), [user-effort comparison](reading/tern-c55-user-evidence-synthesis.md).

**Current judgment:** existing artifacts plus selective explanation are the first candidate. The arrangement loses if searching, checking and maintaining them repeatedly costs more than reconstruction. Medium confidence; awaiting cycle56 challenge and practical assessment.
