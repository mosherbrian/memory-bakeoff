# Cycle59 — batch acquisition is a candidate, not held-out admission

Tern ·26 September2026 · complete: all three panel reports read. [Primary v2](https://arxiv.org/html/2309.17428v2), §§2.1–2.2, 3.1, Appendix B/C.2. [Opinion](opinions/corvid-c59.md).

**Accept:** a pre-built specialized toolset is a real rival to repeated on-demand authoring. Acquisition, abstraction, selection and reuse costs remain separate; shifted inputs can defeat a useful abstraction. This supports considering batch construction for a recurring domain, not choosing it solely because repetition is expected.

**Correct the admission claim:** GPT-4 generates task-specific code; passing solutions are abstracted, then the resulting functions are checked on their **original problems**. This is regression checking after generalization, not validation on additional held-out instances. Held-out downstream evaluation is a different operation. The three validation examples described in §3.1 belong to the LATM baseline, not CRAFT's per-tool admission procedure.

**Bound the guarantees:** grouping by function name and argument count, followed by GPT-4 selection, reduces redundancy but does not prove semantic non-overlap. Nor is all validation independent ground truth: tabular/math construction uses benchmark training data, while VQA includes generated instruction/reference pairs and an LLM semantic-equivalence assessment. Keep that supervision distinction when comparing CRAFT with FRIDAY's critic.

**Decision:** no change to the memo's conditional acquisition advice on this report alone. Borrow the order—check the generalized artifact against the originating case where useful—without imposing a universal checking ritual or calling it a held-out guarantee. The reported roughly $2,500 construction estimate belongs to the released toolsets; it is not a Brian-specific budget or measured break-even against on-demand construction. No experiment or deployment authorized.

**Kiln:** accept checking both the specific solution and its generalized function, and treating names as useful retrieval cues. Withdraw “strictest admission in the survey”: check count does not rank verification quality, and supervision differs by domain as noted above. Table3 does not put abstraction second in every ablation; removing docstring matching hurts more on each reported VQA dataset. Removing name matching costs 9.0/6.6/9.1 SAcc points, not one universal 6.6-point effect. Empty retrieval falls back to ordinary code generation—abstaining from tool injection, not from answering. The toolset-size experiment compares construction subsets; it cannot establish a production lifecycle that only grows. No automated revision/history mechanism is established by this read, although §2.2 explicitly allows human inspection and repair. A registry remains a design option, not a demonstrated missing requirement or guaranteed recovery path. Current-code claims need pinned source links before inheriting paper confidence. [Card](systems/craft.md), [opinion](opinions/kiln-c59.md).


**Cairn:** accept the original-case check after abstraction and component controls. Restrict training-split/ground-truth language to tabular/math; VQA supervision differs. GPT-4 benefits too, so weaker gains do not establish that a model cannot benefit from its own tools. Open-source pilots performed poorly; successful local-host transfer is unestablished, rather than all such models being untested. No automated revision loop is described, but manual repair is explicitly contemplated. The earlier ~$14 estimate belongs to AutoManual, not LATM. Withhold “best-supervised” and name/arity dedup as a universal prescription. [Reading](reading/c59-craft.md).

**Cycle closed:** retain conditional acquisition advice. The useful addition is regression checking after a solution is generalized, with supervision provenance explicit. Batch construction is an option, not the default for every repeated family. No new facility, validation tax, registry or experiment follows; changed-condition reliability and acquisition break-even remain open.
