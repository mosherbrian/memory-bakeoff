# Three kinds of user evidence, three different questions

Tern ·26 September2026 · cycle55 lead synthesis, panel in progress. Existing primary reads only; no new source or experiment.

| Evidence | What it establishes in scope | What it does not establish | Practical consequence |
|---|---|---|---|
| Production memory formation, c52 | System-created memories often appear without an explicit memory command in donated account traces. | User effort saved, correction success, or that all such memories are inferred rather than directly stated. | Agent-owned capture is compatible with observed use; do not require Brian to initiate every entry. |
| Semantic Commit, c53 | Participants can inspect and revise proposed changes in supplied specifications; interaction time and perceived control were measured. | Zero correction cost, real-owner long-term benefit, or a need for universal approval. | Keep meaningful changes inspectable and locally reversible where useful. |
| PAIR, c54 | Real repeated interactions produce accounts of helpful recall, stale assumptions and corrections that fail to persist. | Causal memory benefit, exact failure location, total correction burden, or that its summary/gate is the fix. | Treat repeated correction as a failure worth tracing through the current path; acknowledgment alone does not settle it. |

Sources and primary-reading boundaries: [production formation](tern-c52-production-memory.md), [correction interface](tern-c53-correction-interface.md), [repeated use](tern-c54-pair.md).

**My position before panel synthesis:** the arrangement needs no new service or mandatory user workflow on this evidence. It does need a stronger meaning of “handled”: when a direction applies again, the agent should use it appropriately. A recurrence should prompt diagnosis of the existing mechanism, not automatic addition of another memory layer. A suitable default may solve a mechanical choice; revised scoped guidance may solve an interpretation; refreshed context may solve stale delivery. These remain design judgments, not comparative outcomes from the three studies.

**Work to remove:** duplicate user-facing confirmation and duplicate guidance when existing authorization and an effective execution path already settle the choice. Retain useful rationale and exceptions. Do not infer that successful encoding eliminates all future maintenance.

**Still open:** whether this arrangement lowers Brian's repeated corrections, and whether any alternative does so with less total work. No prospective correction-to-later-use comparison in these reads settles that. Medium confidence in advice; high confidence that formation, edit interaction and persistence reports should remain separate units.
