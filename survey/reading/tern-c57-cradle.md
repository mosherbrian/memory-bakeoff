**The main result for our question:** selection remains explicit. Skill documentation/code/comments are embedded; top-K by task similarity forms a candidate set; the model selects and instantiates skills using current observations and history. Integrating these calls in one runtime relocates ownership, not the judgment. Screenshots inform reflection but do not guarantee correct success detection.

The software appendix is especially useful: direct skill generation was unnecessary for those tasks. Common UI actions and some application-specific or complex skills were supplied. CapCut timeline navigation was calibrated in advance. The authors also report the model treating an opened Save dialog as completion before the final confirmation; prompt rules and examples mitigate that error. This is direct evidence of why observing an outcome is not the same as interpreting it correctly.

**Learning varies by environment.** RDR2 initializes preliminary movement skills and derives others from game instructions; Stardew includes designed composite skills; Dealer's Life2 skips curation with supplied atomic skills; Cities uses exploration plus templates. Do not pool these as one autonomous skill-acquisition result. The supplied IO interface is keyboard/mouse control, not privileged access to game state. External visual grounding and application-specific scaffolding still matter.

**Controls:** §4.3 adapts ReAct-like, Reflexion-like and Voyager-like agents, varying several modules or observation modalities. Those comparisons support integrated-system performance, not an isolated accumulated-skill effect. The main protocol uses repeated runs and human evaluation for games/applications; OSWorld supplies a separate scripted-evaluation setting. Code/documentation/name checks for new skills are admission checks, not demonstrated semantic correctness. Episodic summarization and recent-frame memory likewise do not prove lossless history.

**Opinion:** borrow observation-informed planning and outcome reflection when they reduce real uncertainty. Do not add continuous perception where a discrete observation suffices, and do not treat our baseline as a batch-review-only system. Keep code artifacts, selection and current-state interpretation accountable regardless of packaging. High confidence in explicit selection and supplied-skill distinctions; medium transfer to Brian's CLI/model operations. No deployment winner or memory-specific benefit estimate.
