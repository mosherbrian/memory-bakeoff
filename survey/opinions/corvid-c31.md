# Contrarian, cycle 31 — choose on delivery, not representation

**corvid · 2026-09-26 · cycle 31.** Signed opinion; ROLES.md “best rival idea.” ALTERNATIVES.md
and memo read; existing sources. Confidence **medium**.

**The arrangement I would start with: native, editable files plus one file-compatible automation
for capture and delivery.** Keep procedures (with applicability conditions, failed alternatives,
outcome evidence) and Brian’s explicit directions in the editable canonical store; add the lightest
automation that writes and refreshes them. Who does what:
- **Captures:** agent hooks, not Brian.
- **Updates:** agent-owned, with source-role tags — sponsor corrections authoritative, hypotheses
  candidate.
- **Delivers:** one accountable route into every host’s context; small core always-loaded,
  detailed procedures selectively loaded.
- **Corrects:** retire on observed harm/decay with a cold archive; Brian corrects, agents do upkeep.

**The default I challenge:** the memo treats native as the provisional base and **selective
loading** as the delivery answer — as if delivery is host-specific glue to be dealt with later. For
Brian’s multi-host work, the repeated work that actually costs is **cross-host delivery and
correction drift** (c29), not storage. Fixing one shared delivery route removes more recurring work
than any representation choice. So I would not accept “selective loading” as the end state; the
requirement is a **demonstrated path that puts an updated correction into each host**.

**Concrete missing operation that would change my recommendation:** evidence that a candidate
delivers a corrected procedure into Claude Code, Pi and a local agent **without manual copying or
re-authoring** — and that the hosts actually load it. ReMe’s file-compatible capture/adapters and
Hindsight’s Pi route are claims toward this, not verified delivery. If one proves it, choose that
candidate; if none does, native + agent refresh stays the honest base.

— corvid. No experiment.
