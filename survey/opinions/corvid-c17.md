# Contrarian, cycle 17 — switch the derived-belief layer, not the store

**corvid · 2026-09-26 · cycle 17.** Signed opinion, not an audit. ROLES.md: *“the strongest case
AGAINST the current position memo, and for the best rival idea.”* Sources: Letta MemFS/reflection
docs; Hindsight observations + Pi integration docs; c9/c10/c14/c16 readings. `[read]`

**Recommendation today.** Native files remain the best **base**, but a pure native/watch stance is
now **excessive conservatism for the preference layer**. Switch to an integrated memory facility
for **derived beliefs and evolving preferences**, keep native for **procedures and explicit
directions**:

- **Procedures and directions stay native.** Portable across Claude Code/Pi/local, editable,
  diffable, and able to carry an executable helper + artifact check. No integrated system read so
  far solves the real hazard — a prerequisite that changed while commands still exit zero. Native
  is where a checker can live.
- **Preferences/inferred tendencies move to an integrated facility.** This is the concrete missing
  operation: **freshness-verified correction with retained history and grounded sources**.
  Hindsight’s current docs supply exactly that — observations backed by **supporting-memory quotes
  and a proof count**, **previous versions preserved**, contradiction captured as evolution, a
  **stale** flag forcing verification against raw facts, and a **Mental Models** tier that keeps
  user-curated directions *above* agent beliefs. Native notes have none of this built in; the agent
  would have to hand-roll staleness, history and grounding. That is a real facility, not a label.

**Upkeep, honestly.** “Agent-maintained native files” already removes Brian-as-author; the delta is
machinery, not authorship. Integrated upkeep is background consolidation (no Brian in the loop),
at the cost of a service, extraction/dedup risk (0.97 threshold can fold distinct beliefs), and a
model call per consolidation. Native upkeep is zero-install but spreads the same checks across
ad-hoc agent behavior.

**Why this is a switch, not a migration.** Brian’s first cost is procedural re-learning; the
integrated facilities help most on the *second* cost (preferences) and barely help the first.
Migrating procedures would trade a checkable artifact for an observation with no applicability
test.

**One evidence-sensitive reversal.** If a low-cost native script/agent skill provides
freshness + history + source-grounding for the preference layer, or if the integrated service’s
extraction/dedup proves unreliable on Brian’s real corrections, stay native. Conversely, evidence
that integrated preference correction reduces repeated corrections without added maintenance would
justify moving **procedures** too.

**Verdict:** adopt the integrated facility **for the derived-belief/preference layer now**; keep
native as canonical for procedures and authority. **Medium-high confidence** that native-only for
preferences is now over-conservative; **medium** on the service choice.
