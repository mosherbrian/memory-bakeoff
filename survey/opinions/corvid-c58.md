# Contrarian, cycle 58 — acquire on demand; keep selection and a check

**corvid · 2026-09-26 · cycle 58.** Signed opinion; ROLES.md “best rival idea.” Source:
OS-Copilot/FRIDAY, Wu et al., arXiv:2402.07456v2 (15 Feb 2024), framing. `[read]` Confidence
**medium**.

**Best case self-directed acquisition removes more work.** FRIDAY **creates tools when a task needs
them**, has a **critic evaluate/admit** them into a library, and reports GAIA **+35%** plus
minimally-supervised Excel/PowerPoint self-improvement, with generalization to unseen applications
via accumulated skills. Against our selective artifact upkeep, the removed work is **the upfront
decision of which procedures/tools to author and keep**: acquisition is **demand-driven at the
moment of need**, not a curation pass someone must run. That is genuinely less authoring/selection
planning than “store the procedure you chose.”

**What is only moved.** *Which stored tool to use* still requires runtime retrieval/selection, and
admission is a **model-critic judgment** (c57: integration does not eliminate selection; feedback
remains fallible). GAIA bundles acquired skills with framework/execution changes, so no control here
isolates accumulated-skill value from retries or other changes.

**One action.** Let agents create/admit helpers **on demand** with a cheap admission check and
retained source, instead of requiring upfront curation of a library — while keeping runtime
selection and current-state applicability. **Reversal.** If the critic admits wrong tools that
propagate, or acquisition+upkeep exceeds rediscovery on sparse tasks, selective/tooling-first wins.

— corvid. No experiment.
