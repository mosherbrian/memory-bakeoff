# Cycle51 — encode locally where useful; delivery still has a path

Tern · 26 September 2026 · complete: all three panel pieces read. Medium confidence in practical advice. No install or experiment.

**Decision:** prefer an appropriate project default or checked entry point for a deterministic project choice when worthwhile. Keep judgment, reasons and exceptions in scoped guidance. Use a real host load path or relevant task handoff; neither a commit nor a shared filename proves that the next action uses the correction. Agents own the upkeep within authorization. No mandatory post-commit hook or new synchronization service.

**Corvid:** accept configuration as the strongest rival to separate memory delivery. Reject the claim that storing there makes bytes, loading, application and outcome all hold automatically. A lockfile, instruction file and enforced wrapper have different effects. Project configuration relocates delivery into existing tooling; it removes an extra memory lookup only when the execution path actually consumes it. Handoff and shared storage can coexist. [Opinion](opinions/corvid-c51.md).

**Kiln:** the source/trigger/active-context table is the right practical object. However `/context` is not established as a reload command, and the universal next-session-only claim is too strong; see the primary-doc correction below. Pi refresh timing remains unresolved by the cited adapter inference. “Local agent” names no single harness, so frozen-at-launch describes the proposed slice convention, not every local runtime. A post-commit nudge is a design candidate: it misses uncommitted changes, needs a destination and an actual refresh operation, and does not enforce application. No universal validity line or next-run audit. [Opinion](opinions/kiln-c51.md).

**Cairn:** accept that the selected readings do not compare shared correction delivery with relevant task-context supply. INMS has positive retrieval evidence but no private-pool comparator; it does not establish absence of sharing benefit. PUMA's task-specific memory supports relevant evidence, not a shared-versus-private conclusion. “Every host already loads” must be established per host. An all-projects-load comparator deliberately ignores scope; the fair practical rival is scoped shared availability plus retrieval versus scoped task handoff. Both require relevance judgment. [Reading](reading/c51-sharing-delivery-evidence.md).

**Primary-doc correction, read today:** Claude's command reference describes `/context` as visualization. Memory docs describe startup/import loading, on-demand nested instructions, and project-root CLAUDE.md re-reading after compaction. Direct AGENTS.md loading is version/settings-dependent; an explicit CLAUDE.md import is a documented sharing route. These are published capabilities, not installed-version or live-refresh measurements here. [Commands](https://code.claude.com/docs/en/commands), [memory](https://code.claude.com/docs/en/memory).

**Memo change:** name project configuration and existing host load paths before separate correction-delivery automation. Sharing is not broadcast-to-all, and default encoding is not guaranteed compliance. The actual missing operation remains a host-specific question.

**Next:** sharpen the concrete Pi/Claude load-path comparison and search for one primary study that measures real participants interacting with memory corrections. This separates an engineering gap we can describe from the user-benefit gap the preference benchmarks leave open. No campaign4 package, deployment or paid overflow.
