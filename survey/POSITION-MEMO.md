# Agent memory: keep what was learned, recheck what changed

> State tells the agent what to do now. Memory tells it what it has learned. History lets it reconstruct what happened. Artifacts establish what is true. Executive reasoning decides what it means.
>
> Don't delete the past just because you stop putting it in every prompt.

— **Brian**, [principles](inputs/BRIAN-PRINCIPLES.md).

**Tern · cycle65 ·26 September2026.** Brian's costs are **re-learning procedures first, repeating preferences second**. My recommendation is a small, agent-maintained body of reusable guidance, one source for explicit directions, and recoverable supporting history. **Medium confidence; no product winner established.** Brian should not become its librarian. Start with existing facilities; agents draft, revise and refresh guidance. Host delivery still needs checking.

**Three ranked bets**

1. **Retain the useful method in the form that fits.** Keep the smallest useful explanation, example, routine or helper. Preserve ordering, conditions, alternatives and source evidence. Choose code or prose to fit the task. Prefer a worthwhile tool/default fix to repeated mechanical instructions. Avoid duplicate guidance that merely restates it; retain useful rationale and exceptions. Observe consequential changing state when a cheap, safe check can settle it; past success is not current success. Distinguish bad guidance, bad application and changed conditions before revising. Agents draft; some recovery notes help only the current job. Consider bounded practice for a missing competence after checking existing tools and interface guidance. Reverse this bet when reconstruction costs less than upkeep and misapplication. [Procedure evidence](reading/tern-c2-outcome-evidence.md), [worked arrangement](PROCEDURE-WORKED-ARRANGEMENT.md).
2. **Share durable learning by scope; hand off the current task.** Keep explicit directions in one authoritative source with host views, separate from inferred tendencies. Agents may turn useful examples into editable inferred rules without policy training; keep scope and attribution revisable, especially for hypothetical or third-person material. Preserve intent and supersession: a quoted user sentence is not automatically a standing instruction. Judge preference memory by useful responses and actions under actual constraints. A correction must survive into relevant later use, not merely receive acknowledgment. Put deterministic project choices in suitable defaults when worthwhile; use actual host load paths for scoped guidance. Share corrections across compatible hosts; pass live objectives, state and decisive evidence explicitly. Shared files already qualify—service access does not guarantee that a correction reaches an existing prompt or gets used. Preserve disagreements while resolving scope and current relevance. Make consequential or ambiguous revisions inspectable and locally reversible where useful; this need not add an approval step. Reverse promotion or sharing when it spreads mis-scoped guidance faster than correction. [Preference evidence](PREFERENCE-EVIDENCE.md), [sharing judgment](panel-response-c29.md).
3. **Keep the past recoverable; select what guides the next action.** Preserve failures and superseded directions without continually recommending them. Retention, discovery and applicability are separate; selective loading must repay its added judgment and cost. Withdraw invalid current guidance while keeping a usable recovery path; low success after retrieval alone does not establish invalidity. Resolve short histories while reading; maintain a recoverable current view when repeated resolution becomes costly. Assemble the next view from the task, applicable directions and known dependencies; expand when evidence is missing, keeping related evidence together. This needs no separate routing stage or fixed context recipe. [Retirement](panel-response-c26.md), [recovery](reading/tern-c18-reading-and-host-path.md).

**What to buy:** compare missing operations, not “native versus integrated.” ReMe offers file-compatible capture/consolidation; Hindsight offers derived-observation machinery; Letta offers an integrated runtime. Compare the current operations and version, not a historical paper pipeline. Their costs and behavior on Brian’s hosts remain unverified. Choose automation that removes actual work; price acquisition, retries, evaluation, upkeep and user attention as well as retrieval. [Alternatives](ALTERNATIVES.md), [roster](ROSTER.md).

| Layer | Keep this responsibility |
