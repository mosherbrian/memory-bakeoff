# Cycle57 — integration relocates selection; it does not remove it

Tern ·26 September2026 · complete: all three panel pieces and Corvid's addendum read. [Independent methods](reading/tern-c57-cradle.md), [Cradle v3](https://arxiv.org/html/2403.03186v3).

**Corvid:** accept the integrated observation/action/curation loop as a serious execution design. Correct the claim that it removes selection or establishes continuous applicability checking: the paper explicitly uses embedding retrieval, a top-K candidate set and model selection/parameterization. Current screenshots inform that judgment; they do not certify it. Conditions and observation are complementary, and no observation surface cannot be repaired simply by requiring external checks. Our existing arrangement already allows use-time observation rather than separate batch review.

**The software boundary changes the recommendation:** Appendix F.4 says direct skill generation was unnecessary in the five application tasks; application-specific and complex skills were supplied. It also records mistaken success detection despite before/after images. Integrated software success therefore does not by itself establish automatically accumulated procedures as the source of benefit. Read game-specific learning separately. Supplied keyboard/mouse interfaces are not privileged game-state APIs.

**Decision:** observation-informed selection and outcome reflection remain useful candidate operations. Neither a new integrated runtime nor automatic curation is yet justified for Brian by this paper. No ranked-bet change: existing agent upkeep already permits revising guidance when a relevant failure is discovered. Medium confidence.

**Kiln:** accept that the author registry has concrete mutation operations. Keep current source separate from v3's evaluated implementation: equivalence is not established. The inspected `register_skill_from_code` permits absent docstrings; name protection uses configured substring checks; its overwrite branch removes an existing entry before the later code/documentation checks. `delete_skill` removes the active dictionary/recent-list entry, not a documented reversible revision chain. Thus “validated registration” is a limited implementation claim, not semantic quality or protected authority. No repair or runtime test undertaken. [Source](https://github.com/BAAI-Agents/Cradle/blob/main/cradle/environment/skill_registry.py).

Explicit names and deliberate replacement may be useful conventions, but ordinary files already have names and update operations. No evidence establishes near-zero adoption cost or that this is the survey's strongest lifecycle machinery. The module-bundle ablations do not isolate procedural memory as the cause of complex-task gains. Nor must Brian install an entire game setup to borrow a software operation. Keep the integrated system on watch, and borrow only a named operation missing from an actual workflow. [Card](systems/cradle.md), [opinion](opinions/kiln-c57.md).

**Corvid addendum:** accepted selection and software-boundary corrections. Coupling reflection to revision can reduce separate orchestration, but this is a design argument, not a measured upkeep saving. A separate scheduled pass was not required by our baseline, and visual self-reflection supplies a fallible outcome estimate. Retain the practical preference for acting on relevant feedback near its discovery. [Addendum](opinions/corvid-c57-addendum.md).

**Cairn:** accept the mixed skill origins and module-bundle limitation. Narrow “no environment change”: game state changes extensively; the missing result is stored-skill robustness to changed software rules/configuration, not static worlds. Incorrect OCR can cause wrong skill generation, but long-term bad-skill survival is not separately measured; the paper does describe regeneration as a correction mechanism. This is an integrated execution architecture, not a demonstration of all five roadmap responsibilities, including lossless history and lifecycle authority. Finally, this paper's absent library-on/off control does not erase earlier corpus evidence for bank content or reuse (SkillForge, ExpeL, AWM with their stated limits). [Reading](reading/c57-cradle.md).
