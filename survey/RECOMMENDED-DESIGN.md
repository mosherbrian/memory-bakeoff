Test `python3 -m pytest`/`python3 script.py` denied, `python script.py`/quoted mention allowed, project scope and intended interpreter verified. Check wrapper/absolute-path boundaries. Observe one normal session for false blocks and recovery; roll back the pilot rule if unacceptable, preserving existing protection. Passing proves mechanism/usability, not fewer repeated preferences. **Is most of what we want in MemFS? Yes—inside Letta Code.** Background workers, Git history, structural validation, configurable budgets and harness-managed refresh replace several diligence-dependent chores in one product. Recall history is separate from the file repository. Missing: semantic supersession/valid-time decisions, guaranteed correct application, and measured benefit here. Budget checks are layout/configuration-dependent; `/doctor` warning is not prevention. Letta limits do not automatically match Claude/Pi limits.

**Optional pilot — “Letta Code, one project, one week.”** Components: Letta Code harness + built-in dreaming + MemFS/recall. Report wrong inferences, repetition, cost and repair effort from existing records. Return to the prior runtime if burdens outweigh benefit. **Medium confidence in fit; low in outcome benefit.** No per-entry Brian approval.

**Could Claude/Pi read a synced repo? Yes, as a proposed read-only file view—not the Letta harness.** Letta remains sole writer; separate consumers need enforced read-only access, a small scoped entry view and an existing refresh/load route. GitHub mirroring is asynchronous and can fail. The view does not bring recall storage, background workers, consumer-transcript capture or obedience. Verify delivered commit and host limits; do not build a new sync pipeline for this first trial.
