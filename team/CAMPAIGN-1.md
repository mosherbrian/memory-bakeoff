## Candidate campaigns (add yours; we converge, then propose ONE)

### A. "Adapt when circumstances change" — close the supersession loop on real work (Kiln)

The trial's frozen pre-registration already contains the decisive test: a
deliberate convention change → worker drafts a supersede → recall thereafter
delivers current-only → stale-action events = 0. That is the charter's "adapt
when circumstances change" made measurable. Campaign: run the trial to that
cycle on REAL work (its tasks are real by pre-registration), with the
delivery gate as the instrument. Deliverable: the first end-to-end proof that
an agent's memory adapts under its own workflow — current decision applied,
dead decision never resurfacing — with burden inside the 1–3/day estimate.
Evidence: worker-pi session logs + notify file + confirm receipts.

### B. "The agent notices" — change-aware retrieval triggering (Kiln + whoever owns nudges)

Self-noticing is the measured weakness: the memory is present and correct,
but the agent doesn't LOOK unless nudged, and today's nudge is static.
Campaign: make the trigger change-aware — fire on (new task in known project,
contradiction with a stored decision, resumption after a gap), surface the
relevant record at the moment of relevance. Mechanism is small (nudge
layer/extension, no perseus changes); the metric is the trial's own
recall-usefulness x/y plus burden. Fuses with A: A proves the loop, B removes
the human from the trigger seat.

### C. "Repair the inert pipeline" — upstream capture fix (biggest lever, biggest lift)

Capture is the hole; the vendor pipeline is broken in a way we have receipts
for (no admission evidence → non-serveable forever; no derived lineage). We
hold the source tree (`/var/home/bmosher/perseus-build/src`). Campaign:
patch capture to embed admission evidence + emit lineage CANDIDATES
(not auto-links — candidates a human/agent confirms through our proven
supersede path), rebuild, re-probe with the same two-conversation sequence.
Deliverable: a working capture→admission→delivery pipeline with derived
lineage candidates, benchmarked against the pre-registered trial metrics.
Risk: vendor-surface surgery; needs reviewer + planner sign-off; do NOT
start until A/B evidence says capture is the binding constraint.
