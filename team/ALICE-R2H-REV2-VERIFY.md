## Finding — the documented re-run command is broken by REV-2

`ASSAY-R2H-CLOSE-TRACES-FIX.md` (§Receipts) says:

```
Re-run: python3 scripts/verify-20260912-assay-row1/r2h_close_traces_fix_power_check.py
```

After REV-2, that default run fails:

```
$ python3 r2h_close_traces_fix_power_check.py     # exit 1
anchor not unique/found (0)
```

Cause: the power check treats `--deploy` (default = canonical) as the
**pre-patch** input, searches for the rev-1 anchor, and derives the guarded
variant. Once Stratum applied the patch, the anchor is gone. The check is now
only re-runnable with the rev-1 bytes supplied explicitly:

```
python3 scripts/verify-20260912-assay-row1/r2h_close_traces_fix_power_check.py \
        --deploy team/r2h_deploy.py --out /tmp/r2h-pc     # exit 0, 11/11
```

**Recommended, cheap and receipt-level (owner Assay):**
1. Update the note's re-run line to the `--deploy <rev-1 bytes>` form, naming
   `team/r2h_deploy.py` or the git form
   (`git show HEAD:deploy/r2-habit-20260912/r2h_deploy.py`). The rev-1 bytes are
   durable in canonical git `HEAD` (`b0b761a`), so this is not a lost receipt —
   only a stale command.
2. Optionally have the power check detect "anchor already applied" and say so
   instead of the bare `anchor not unique/found (0)`.

**Related consistency point (not a defect):** the freeze says the deploy package
is "mirrored to `team/`", and `team/r2h_deploy.py` is still the rev-1 file
(`74e7ae86…`) while the canonical package is rev-2. That is *useful* for
reproducing check 3, but it means the `team/` mirror is now stale against the
package being re-sent to Brian. Either update the mirror to rev-2 **and** keep a
sealed rev-1 copy for reproduction, or state the mirror's rev-1 role in REV-2.
Owner: Stratum (freeze owner).
