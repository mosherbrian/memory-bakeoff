# reader-interference-v5, frozen and unrun (Gen116)

**Status: candidate protocol awaiting control-plane review. Not a result.**
No reader, model, endpoint, sidecar, memory engine or GPU was called.

Canonical attempt `results/gen116/attempt3`.
`contract_sha256` `323305e16273d84e07bbfc8e9f696aa4f958c69e3572c9842053d1893b9f4942`.

## What v5 changes, and why

Gen115 established that v4 could not answer its own question. No conflict prompt
told the reader which record was current, so "picked the current value" scored a
guess. The control plane ruled **R-1(a)**: make recency explicit, uniform and
role-neutral.

    effective_revision   an ordinal on EVERY record, identical schema and order
    as_of_revision       an ordinal in the question
    the rule             select the record whose effective_revision equals
                         as_of_revision exactly; otherwise answer INSUFFICIENT

Nothing else may carry recency, and the audit enforces that mechanically:

- no role words in any record statement or id (`current`, `stale`, `superseded`,
  `latest`, `winning`, `correct`, `prior`, `old`, `new`, `canonical`, `authoritative`)
- no progression prose anywhere model-facing (`after`, `initially`, `resized`,
  `previously`, `formerly`, `now`, `then`, `migrated`, `replaced`, and 20 more)
- no numerals in candidate values, so nothing is version-shaped
- conflict order counterbalanced 12/12 across the two conflict conditions, so
  context position cannot encode truth

## The fixture

12 fresh cores, disjoint from the four cores burned in Gen110-115 and from every
value, question and answer string observed there. Each core has two contradictory
values sharing a head noun, matched token count, and length within two characters.

Two biases were found by the audit and fixed rather than described:

| bias | attempt1 | attempt3 |
|---|---|---|
| revision-2 value is longer | 3/12 | **6/12** |
| revision-2 value sorts later | 7/12 | **6/12** |
| revision-2 record id sorts first | 2/12 | **5/12** |

The id fix is structural, not cosmetic. Ids are now derived from an opaque *slot*
with an alternating slot-to-revision map, so a digest cannot track the role even
by chance. attempt1 hashed the revision directly and got a 2/12 split by luck; a
reader that sorted ids would have had a signal we never meant to give it.

5 conditions x 12 cores = **60 unique cases, 60 unique prompts, no repetitions**.
The independent unit is the **core**. Sixty cells are not sixty observations, and
the schedule records that explicitly.

## The response contract

Strict JSON with a machine-readable selection:
`disposition` (RESOLVED/UNRESOLVED/INSUFFICIENT), `selected_record_id`,
`selected_value`, `prior_values`, `citations`.

Eleven mutually exclusive classes, exhaustive over that contract by execution.
The three rules that killed v4 are now enforced:

- **Contradiction is an assertion, never a substring.** Naming both values is
  `UNRESOLVED_BOTH`; a chronology ending at the revision-2 value is
  `CURRENT_WITH_HISTORY` and is a *success*. `EXPLICIT_SIMULTANEOUS_CONTRADICTION`
  requires claiming RESOLVED while naming both values as the answer.
- **Matching is token-aware.** `lane amber` does not match `lane ambergris`,
  `xlane ambery`, or `lane ämber`. Nine witnesses cover containment, case,
  punctuation, negation, quotation, whitespace, Unicode and adversarial collision.
- **Citations cannot rewrite the answer class.** Class is computed from response
  content and canonical values first; citation relation is a separate field. A
  test asserts the class is invariant across four citation sets.

## Integrity

The contract payload contains behaviour tables generated by *running* the parser,
classifier, citation classifier and grader over exhaustive and adversarial inputs,
plus SHA-256 of every source file supplying scientific behaviour — including the
future runner, the future grader and the verifier. The single exclusion is the
contract digest itself.

`scripts/verify_gen116_contract.py` reloads the module from its file path under a
different name, **proves the module and function objects are distinct**, and only
then compares payload digests and all 60 prompt bytes. Gen113's equivalence check
compared a module with itself and passed vacuously; this refuses to.

Mutation witnesses: changing the rule text, the classifier, or a single core value
each move the fingerprint.

## Known limitation, stated plainly

The legacy projection of the sealed Gen114 replies through the v5 ontology agrees
on **18 of 24** cells and differs on 6. It cannot agree fully: v5 has no
`AMBIGUOUS` class, and the old contract had no `disposition` field, so the
projection needs a text adapter. It is marked `NON_CONFIRMATORY`, contributes to
no estimand, and the six differences are listed rather than engineered away.

This is a frozen candidate. Whether it may ever run is the control plane's call.
