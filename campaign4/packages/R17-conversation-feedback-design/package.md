## Required design
1. Pin each selected feedback source. Locate minimal original conversation evidence where available using source session IDs/dates; record exact source locator/hash and distinguish Brian's words from Claude's memory paraphrase. A memory file alone does not prove its origin or authority. Do not copy unrelated/private transcripts or credentials into git. Establish actual rule scope; do not turn a contextual instruction into an absolute slogan.
2. Audit the selected task's ordinary project files/instructions for the same rule. Same ordinary files and natural notes in both arms; do not remove existing guidance. These feedback files ARE persistent files: the contrast is their additional delivery over the specified ordinary workspace, not information unavailable anywhere on disk. Record existing access, curator exposure and any unavoidable leakage. Fresh sessions do not prove blindness. Specify a feasible access boundary for later execution; no new machinery in this round.
3. Freeze six task prompts, memory packet and allocation/order plan before participant outputs. Tasks must request useful deliverables, not ask for the remembered rule or cue a violation. Do not select or discard tasks after seeing control performance. Randomize/counterbalance arm order with fresh sessions; same model, task, ordinary files, budget and tools. No deletion of natural notes. Give memory generation/delivery cost and exposure explicitly; fixed curated packet is a best-case availability test.
4. Define per-task checks BEFORE outcomes. Primary: a usable requested artifact that also complies with the applicable rule. Report usability and violation separately; refusing, omitting the command/URL or doing nothing cannot win. Mechanical checks must distinguish quoted warnings from executable commands, displayed endpoints from bind addresses, and verified PID use from mere token matching. Supply one conforming, one violating and one vacuous/ambiguous hand-written example per check. New small pure checks are permitted as proposed oracles, not presumed valid because they pass selftests. Corvid challenges them independently. Ambiguity remains explicit, never silently green. No historical shell scripts or generated operational outputs executed.
5. Pre-register paired per-case outcomes, rule-level totals, missing/invalid results, no causal or population claim from this tiny purposive set. No arbitrary timing cutoff or post-result exclusion of control notes. Report all cases, including equal success. Improvement would justify further testing of this task class, not adoption or a retrieval claim; equal results would bound this packet/task setting, not end memory research.
