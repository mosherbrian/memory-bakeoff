## Eight operating rules

1. Tern records tier, one-sentence consequence, acceptance check, owner and overall effort/deadline cap at first authorization. For tiers 3–5 this may be one short issue/receipt, not a package bundle. Tier escalation is consequence-based; split mixed work or apply the higher tier to the affected part. No new admission pass for unchanged repairs inside approved scope.
2. Any reviewer may raise a tier with a concrete failure path. Tern resolves ordinary uncertainty by choosing the higher plausible tier provisionally and recording why; lowering requires Tern. Scope/budget decisions remain Brian's. The genuine-undecidability hard stop is unchanged.
3. Size from whole-task/test-run measurements plus margin, not inter-file write gaps. Record the relevant observed timings and estimate in the authorization; reuse existing measurements, without creating another maintained control system. When none exist, label the estimate and use the first bounded run to calibrate. One prospective owned extension may be specified in the original grant (trigger, maximum, owner and total cap); otherwise Tern grants it before expiry within sponsor budget. An extension must update the authoritative grant and re-arm/verify the enforcing timer before the old bound; changing prose alone does not extend execution. No retrospective extension, clock reset, or unlimited 'tests still running' exception. A timeout preserves partial work, not an automatic verdict about its quality.
4. Tiers 2–5 may iterate within one approved time/effort box; material scope changes need an amendment, not each small fix. Material means changing the authorized outcome, acceptance criterion, research inputs/hypothesis, permissions or overall cap. A repair to meet an existing criterion is ordinary iteration even though behavior changes. Tier 1 retains one attempt plus one repair; distinguish implementation repair from new hypotheses and data collection. An exhausted box requires a disposition and explicit further allocation, never silent continuation.
5. Stand-ins prove only what their tested interface fidelity supports. Check the actual entrypoint/composition early. A stand-in fidelity check is one focused, budgeted interface check where sufficient, not a new review round by default. Use deterministic receivers for notification tests, actual workers where worker behavior is the subject. Changed critical live integration (including authority, routing, or supervision affected by units/config/release-artifact changes) needs a focused real witness; unchanged code does not require another whole-suite live run. Freeze released executable/config inputs and research evidence; a typo/citation fix can be reconciled from Git without a new author round.
6. Routine progress is status. An escalation names an action, owner, bound, exact acknowledgement command and resolution condition. The loop drives admitted handoffs; cairn owns exceptions and liveness, not manual polling or a second control ledger. Every dispatch includes the exact completion command when one is required. Never infer identity from suffixes or filenames.
7. Tern approves tier 1 research claims/releases and production changes of any tier, and may preauthorize a concrete bounded sequence. The named independent reviewer can accept tiers 3–4 deliverables and delegated plan corrections inside that scope without another director gate. Tier 5 needs no compulsory reviewer/signature. Delegation cannot expand permissions, spend, install scope or change an accepted research question.
8. Author is not verifier for tiers 1–3. Keep honest COMPLETE/INCOMPLETE, append-only corrections, immutable accepted outputs and negative research evidence, and both charter hard stops. Preserve exact executable identity for a reviewed release without requiring hand-authored manifests for every document. Correct provenance defects locally when existing immutable evidence resolves them; do not call a missing test result a formatting defect.

## Lightweight measurement — sponsor request, 2026-09-24

Effective from R1-evidence-synthesis. Tier 5 recording effort; no new package, admission, verifier, software or control ledger. Tern owns a small `metrics.json` in each package at terminal disposition, derived from existing runtime/loop/claim/review/signature receipts. Intermediate values may remain pending; do not invent zeroes. No change to an in-flight contract, acceptance check or allocation.

Record four measures:

1. **Actual minutes** by author, review, admission and live execution. Use observed start/end intervals, sum separate active turns/process runs where available, and cite the timing source. Exclude known queue/idle/usage-reset waits from active effort; show those separately when available. Dispatch-to-claim elapsed is labelled elapsed, never silently active effort. If only a ceiling or uncertain timestamps exist, record unknown (or an explicitly labelled partial observation); no ceiling substituted for actual time. Automated tests inside an author interval are included there, not also live minutes. Combined admission/source-first assessment is charged once to admission; retain that qualification. These are observed seat/process minutes, not inferred CPU time or token cost.
2. **Round overhead** = (review rounds + admission rounds + signature rounds) / author rounds. Include initial and repair rounds. A round is one bounded assignment returning a verdict/claim or ending at its bound; ordinary tool calls and status updates are not rounds. Count a distinct substantive director release/acceptance gate once as a signature round, even without a file called signature. Grouped approval of a bounded sequence counts once, not per command. Record the four counts and the computed ratio; zero author rounds => ratio unknown/not applicable. Failed/rejected rounds count. No double counting an admission as a review.
3. **Non-PASS verdicts**: evidence-format-only versus substance. Format-only means an existing result is not bound/presented correctly (e.g. stale hash); absent execution, unsound checks or unsupported conclusions are substance. Mixed verdicts count once under substance, with mixed count noted. Unknown classification stays unknown. Include independent admission/review verdicts, not author INCOMPLETE claims, and retain total verdict and non-PASS denominators. Do not relabel historical verdicts.
4. **Author/review/etc. rounds ending INCOMPLETE because of time box or usage**: counts for box-only, usage-only, both, and unknown cause; source references per event. Preserve actual verdict spelling (e.g. BLOCKED at timeout) while counting an unfinished round by its cause. A completed FAIL is not a box-limited INCOMPLETE.

At terminal record assigned tier (and any changed-tier work separately), initial/final granted ceilings as context, and evidence references. Aggregate per tier by summing minutes and round counts; compute the pooled overhead ratio from those counts, not the mean of package ratios. Do not claim overhead improved by mixing tier 1 research with tier 2–4 operational work.
