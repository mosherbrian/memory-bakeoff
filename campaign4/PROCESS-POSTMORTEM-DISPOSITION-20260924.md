## Eight operating rules

1. Tern records tier, one-sentence consequence, acceptance check, owner and overall effort/deadline cap at first authorization. For tiers 3–5 this may be one short issue/receipt, not a package bundle. Tier escalation is consequence-based; split mixed work or apply the higher tier to the affected part. No new admission pass for unchanged repairs inside approved scope.
2. Any reviewer may raise a tier with a concrete failure path. Tern resolves ordinary uncertainty by choosing the higher plausible tier provisionally and recording why; lowering requires Tern. Scope/budget decisions remain Brian's. The genuine-undecidability hard stop is unchanged.
3. Size from whole-task/test-run measurements plus margin, not inter-file write gaps. One prospective owned extension may be specified in the original grant (trigger, maximum, owner and total cap); otherwise Tern grants it before expiry within sponsor budget. No retrospective extension, clock reset, or unlimited 'tests still running' exception. A timeout preserves partial work, not an automatic verdict about its quality.
4. Tiers 2–5 may iterate within one approved time/effort box; material scope changes need an amendment, not each small fix. Tier 1 retains one attempt plus one repair; distinguish implementation repair from new hypotheses and data collection. An exhausted box requires a disposition and explicit further allocation, never silent continuation.
5. Stand-ins prove only what their tested interface fidelity supports. Check the actual entrypoint/composition early. Use deterministic receivers for notification tests, actual workers where worker behavior is the subject. Changed critical live integration needs a real witness; unchanged code does not require another whole-suite live run. Freeze released executable/config inputs and research evidence; a typo/citation fix can be reconciled from Git without a new author round.
6. Routine progress is status. An escalation names an action, owner, bound and resolution condition. The loop drives admitted handoffs; cairn owns exceptions and liveness, not manual polling or a second control ledger. Every dispatch includes the exact completion command when one is required. Never infer identity from suffixes or filenames.
7. Tern approves tier 1 research claims/releases and production changes of any tier, and may preauthorize a concrete bounded sequence. The named independent reviewer can accept tiers 3–4 deliverables and delegated plan corrections inside that scope without another director gate. Tier 5 needs no compulsory reviewer/signature. Delegation cannot expand permissions, spend, install scope or change an accepted research question.
8. Author is not verifier for tiers 1–3. Keep honest COMPLETE/INCOMPLETE, append-only corrections, immutable accepted outputs and negative research evidence, and both charter hard stops. Preserve exact executable identity for a reviewed release without requiring hand-authored manifests for every document. Correct provenance defects locally when existing immutable evidence resolves them; do not call a missing test result a formatting defect.
