# Fleet runbook

Written 2026-09-20 from the running system. Every port, path and unit name
below was read off the machine, not remembered.

Audience: whoever picks this up next, including a future version of me. It
assumes nothing about the project's history.

## 1. The shape of the thing

A **seat** is one AI agent. It is a terminal session running some agent tool,
supervised by `agent-deck`, living in a `tmux` session.

A **lane** is how a seat talks to a model provider. It is a wrapper script that
makes any provider look the same to the seat.

The **poller** is the only thing that hands out work. Nothing else dispatches.

The **board** (`team/QUEUE.md`) is the single source of truth for what is being
worked on. Agents write prose into it. The poller writes computed state into a
separate column and never touches the prose.

Work flows: a sprint opens with rows on the board -> the poller wakes a seat to
produce each row -> a *different* seat verifies it -> the poller computes the
row as done from files on disk, never from anyone's say-so -> the sprint closes.

## 2. agent-deck — the seat supervisor

Binary: `~/.local/bin/agent-deck`, v1.16.4 (v1.16.10 is available).
State: `~/.local/share/agent-deck/profiles/default/state.db`, SQLite.
Config and scripts: `~/.config/agent-deck/`.

It registers 18 seats, keeps each in a named tmux session
(`agentdeck_<title>_<hash>`), tracks status, and can wake a seat with a message.

```
agent-deck list                    # what exists and its status
agent-deck session start <name>    # bring a seat up
agent-deck session stop <name>
tmux attach -t agentdeck_<name>_*  # watch one work
```

**Seat creation is slow, not broken.** `agent-deck session remove --force`,
`add`, `session set extra-args`, `session start` does work — but on 2026-09-20
the seat appeared about fourteen minutes after the start command, with no
output and nothing in any log in the meantime. Do not conclude it has failed
because nothing happens immediately; check `tmux ls` for
`agentdeck_<name>_<hash>` before launching a replacement. Two overseers ran in
parallel for two hours because of exactly that mistake.

A plain tmux session is the fallback, and is how `clawdbot` runs:

```
tmux new -d -s overseer -c ~/fleet-overseer \
  'claude --channels plugin:fakechat@claude-plugins-official --dangerously-skip-permissions'
```

## 3. The lanes (ACP wrappers)

ACP is the agent client protocol — the thing that lets one seat program talk to
any model backend. Each `acp-*` script in `~/.config/agent-deck/` is one lane.
There are 24. The ones in current use:

| Lane | Provider | Used by |
|---|---|---|
| `acp-zcode` | Z.ai GLM-5.3-Flash, via ZCode | `kiln-flash` — the worker |
| `acp-dsh` | DeepSeek V4.1 Flash, DeepSeek's own API | `corvid-dsh` — the verifier |
| `acp-fable-worker` | Claude Fable 5.1 | `plumb-fable` — writes the gates |
| `acp-oai-worker` | gpt-6-astra via Codex | `anvil-oai` — the planner |
| `acp-pi-worker` | local Qwen3.8-27B on the office box | `cairn-pi` — the conductor |

Everything else in that directory with an `acp-` prefix is a variant from an
earlier configuration. **Most are dead weight** — see §10.

Rule enforced by `fleet-tool-guard`: every lane must stay on `tool=shell`.
Lanes drift off it and stop working; the guard reports the ones that will not
stay.

## 4. The poller

`~/conductor-chat/workers/fleet-poller.sh` — 2,388 lines of bash, run by
`fleet-poller.service` with `Restart=always`.

It sweeps every few seconds and does five things:

1. Reads the board and computes each row's state from **files and exit codes**,
   never from prose.
2. Wakes a seat to produce a row that needs producing.
3. Records that wake in the **dispatch ledger**, append-only, at
   `~/.local/share/agent-deck/conductor/glm/dispatch.log`. This is how
   authorship is known. A file an agent can edit is not evidence about that
   agent.
4. Wakes a *different* seat to verify. A verdict counts only when the verifier
   is not the ledger's recorded author.
5. Escalates when a row will not move.

It touches `$DIR/alive` every sweep. `poller-liveness.timer` pages if that file
goes stale — which is the answer to "who watches the watcher".

**There is a second copy** at
`~/.local/share/agent-deck/conductor/glm/fleet-poller.sh`. Both must be edited
together. They have diverged before. This is a known hazard, not a design.

**Editing it while it runs:** write beside the target and `mv` over it. Bash
holds the inode; truncating in place corrupts a running script.

## 5. The conductor web UI

`~/conductor-chat/server.py`, 3,857 lines of Python, run by
`conductor-chat.service`. Listens on port **8421** (TLS on 8443), bound to the
ZeroTier address only, token-authenticated. It is the phone interface: read what
each seat is doing, send it a message.

`agent-deck web` runs separately on port **8420** — the fuller desktop UI, same
ZeroTier-only restriction.

Both read tmux panes directly. The UI shows a seat's *role* from the declared
constant `CONDUCTOR_SEAT`, not from its name — an earlier version guessed the
role from whether the title began with `conductor-`, which was wrong for two
days after the conductor moved.

## 6. Costing

Four separate things, which is three more than it should be.

- **`fleet-spend-stop`** — the one that works. Counts today's dollars against a
  daily allowance derived from a period budget, and stops dispatch at the
  ceiling. `fleet-spend-stop --status` prints, today: *$0.51 of $2.58 spent
  (20%), $33.35 left of $60 over 11 days*.
- **`go-budget`** — 1,379 lines encoding one provider's billing rules, checked
  against the actual bill.
- **`lane-meter`** — writes per-lane token counts into agent-deck's
  `cost_events` table. **It records 0 dollars for every event and stopped
  writing on 2026-09-14.** The token counts are real: 29.6M in, 25.1M out, 6.0B
  cache reads. The money column is not.
- **`fleet-quota` / `fleet-codex-quota` / `fleet-credits`** — three tools
  reading remaining allowance from three providers.

**If you need to know what the fleet is costing, use `fleet-spend-stop
--status`.** Ignore `cost_events`.

## 7. Escalation and supervision

This is the newest part, all built 2026-09-20, and the part most likely to be
worth keeping.

- **`escalations`** — the durable ledger, append-only, at
  `~/.local/share/agent-deck/escalations.jsonl`. Acknowledgements are appended,
  never edited over the original.
  ```
  escalations --pending                      # what is unanswered
  escalations --add <kind> --source <who>    # raise one, text on stdin
  escalations --ack <id> --note "<what happened>"
  ```
- **`notify-claude`** — pushes an escalation into every running Claude session
  it can find, by looking at which process owns the listening socket rather
  than assuming a port.
- **`fleet-stalled`** — asks only "has any work output been written in the last
  20 minutes", during the working window. Deliberately knows nothing about
  gates, seats or quotas. Runs every 5 minutes. Escalates if it cannot measure
  anything, because a detector that silently stops detecting reads as calm.
- **`escalation-watch`** — pages a human for anything unacknowledged past 45
  minutes, and for any problem that recurs after being marked fixed.
- **`fleet-overseer`** — a Claude session that reads the ledger, verifies the
  claims itself, fixes what is mechanical, and acknowledges with what it
  actually did. Runs in tmux session `overseer`. Its charter is
  `~/fleet-overseer/CLAUDE.md`.

## 8. The research machinery

- **`sprint-next`** — closes a sprint and opens the next one.
- **`sprint-council`** — three seats advise, the planner decides.
- **`sprint-status`** — computes the board state for humans. Zero model calls.
- **`gate-batch` / `gate-write`** — write the tests. The gate author sees the
  row text and the *shapes* of the frozen inputs, never the implementation.
- **`rowcheck`** — computes one row's evidence state as JSON.
- **`rowguard-prereg` / `rowguard-claimlock`** — one writer per row; the
  registered metrics must match the verifier's checklist.
- **`tools/rd_index.py`** — recomputes the corpus index from the tree. Indexes
  top-level `*.md` plus `verdict.json`, `design.md`, `declaration.json` and
  `check.py` inside each experiment directory.
- **`tools/rd_label.py`** — labels documents with a local model. Keyed by
  content hash, so re-running only costs new or changed files. Set `RD_LABELS`
  to write a separate cohort.

## 9. Daily operation

```
sprint-status                       # what the sprint is doing
escalations --pending               # what is unanswered
fleet-spend-stop --status           # what it is costing
systemctl --user list-timers        # what is scheduled
tmux attach -t overseer             # watch the overseer
```

The window opens at 08:00 and closes at 18:00 local. Gates are written by
`gate-batch.timer` at 10:00.

# 10. Keep, or examine

The division below is a recommendation with a stated reason for each line. It
is not a decision.

## Keep — these earn their place

| Component | Why |
|---|---|
| **The dispatch ledger** | The only thing that makes authorship a fact instead of a claim. Everything about verifier independence rests on it. |
| **Computed row state** | Removes prose from every state transition. Four separate bugs came from matching words; this is the class fix. |
| **The gate pair, minus the blindfold** | Author and verifier being different seats is the whole guarantee. See the caveat below. |
| **The escalation ledger** | Durable, append-only, survives restarts. Cheap. It is what made today's failures countable. |
| **`fleet-stalled`** | The only alarm with no condition predicate, so it is the only one that can catch a failure nobody anticipated. |
| **`fleet-overseer`** | Proved itself within five minutes by finding a defect in a fix I had just shipped. It is the difference between alarms that fire and problems that get solved. |
| **`fleet-spend-stop`** | The one costing tool that produces a correct number. |
| **`rd_index.py` / `rd_label.py`** | Recomputed from the tree, hash-keyed, free to re-run. The corpus work is the healthiest thing here. |
| **The 112 checkers and their exit contract** | Real, mechanical, cheap. They catch things. |

## Examine — plausibly overhead

| Component | The question to ask |
|---|---|
| **~100 backup and retired scripts** in `~/.config/agent-deck` | 180 files, 79 live. The rest are `.bak`, `RETIRED-`, `ROLLBACK-`, dated copies. Deleting them costs nothing and removes a large surface for picking the wrong file. |
| **19 unused ACP lanes** | Five are in use. The other 19 describe configurations that no longer exist. |
| **The second poller copy** | Two files, one job, already diverged once. One should be a symlink or one should go. |
| **The quota ladder — 6 components** | `fleet-quota`, `fleet-codex-quota`, `fleet-credits`, `fleet-failover`, `fleet-ratio`, `go-budget`. One of them, `fleet-failover`, parked the whole fleet hourly because it read an empty quota reply as "exhausted". Ask what each is for and whether the failover behaviour is worth its risk. |
| **`lane-meter` and `cost_events`** | Records zero dollars and stopped seven days ago. Either fix it or delete it; a meter that reads zero is worse than no meter, because it looks like an answer. |
| **`fleet-discipline` (355 lines) and `fleet-ratio` (374 lines)** | Both measure how the fleet spends its effort. Neither has changed a decision. |
| **The 3,857-line web server** | It is a viewer. Ask how often it is actually read, and whether `sprint-status` in a terminal does the same job. |
| **`fleet-window`** | Built entirely around a promotional period that expires 2026-09-20. After today it points at nothing. |
| **`escalation-watch`** | Its job is to page a human when nothing has answered. If the overseer works, this is a backstop for the backstop. Keep it only until the overseer has earned trust. |
| **The gate blindfold** | Writing a test from the row text alone, with no knowledge of the system, is what produced 28 rewrite rounds and two gates that still fail. The *independence* of author and verifier is what gives the guarantee. The *ignorance* of the gate author is what costs. Pre-registration — the test written and hash-pinned before any build, by a seat that understands the system, verified by a different seat — keeps the guarantee and drops the cost. This is the single largest open question in the design. |

## The rule that should govern the next round

Every contraption in §10's second table was added to prevent something that had
gone wrong once. Each was locally reasonable. Together they are why twenty
defects in one day were all in the coordination layer and none in the science.

Before adding a mechanism, ask what it lets you **delete**.
